PayKit is a TypeScript-first, server-side Stripe billing framework for modern SaaS.
It sits inside your app, handles the Stripe lifecycle, and keeps the billing state your
application needs locally.

PayKit does **not** process payments. Stripe still runs checkout, stores payment methods, and
moves money. PayKit owns the application billing layer around it.

<Callout type="warn">
  These docs describe the planned MVP surface. The package is not public yet, so code examples are
  mock examples written against the intended server API.
</Callout>

## What the MVP covers

The first docs story follows one narrow loop:

1. Create a Stripe-hosted checkout or payment method flow
2. Receive Stripe webhooks
3. Normalize those webhooks into one PayKit event model
4. Sync billing state into PayKit-owned Postgres tables
5. Charge a saved payment method later through one server API

Subscriptions are intentionally **not** the core docs story right now.

## Architecture

```txt
Your App -> PayKit Core -> Stripe
```

That split matters:

- your app calls one server-side API
- Stripe details stay behind a typed integration
- webhook payloads become normalized PayKit events
- your app reads local billing state instead of stitching together Stripe APIs

## Core principles

- **Billing layer, not payment processing** — Stripe moves money while PayKit manages billing state
- **Local state is part of the product** — PayKit persists the billing state your app needs
- **Postgres first** — the MVP assumes PayKit-owned `paykit_*` tables
- **Keep the abstraction narrow** — the initial promise is checkout, saved methods, webhooks, and charges
